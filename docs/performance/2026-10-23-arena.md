# 对局页性能优化

## 范围

保留原生页面、背景视频、头像/装备/宠物、名牌、掉落预警、组队闪爆、表情、规则与服务端通信协议。本地跑动调度更新为 16ms，按实际经过时间推进。

## 根因与修改

1. 名牌每人有 30 个候选位置，拥挤时每帧重新选位，产生上下左右跳动和名字脱离头像的问题。现将名字固定在本人头像下方，仅在场地边缘夹紧坐标；本人名牌优先显示。候选搜索和碰撞打分整段移除。
2. 原来人物移动会整体重传玩家数组与头像、装备等静态字段，并对四组新旧数组进行 JSON 序列化比较；现稳定成员按 setData 字段路径提交变化，成员增删、重排时提交完整数组。
3. 同一状态的时间、名次、主题与场景字段合并为一次 setData。
4. 视图提交采用完成回调控制：同一时刻提交一帧，期间收到的状态合并为最新帧。名次等 HUD 在等待期间变化后恢复时，也以最新状态为准。
5. 人物、掉落物与名牌使用 translate3d 移动。本人头像与名牌直接呈现最新位置，不附加过渡；其余元素通过 16ms 本地 / 100ms 联网线性过渡衔接位置。移动福袋使用原始图片，飘字使用 transform 动画。

## 操控延迟修复（2026-11-10）

原本本地规则每 50ms 推进一次，位置还经过 50ms CSS 过渡，拖动后需要等待规则帧与动画，转向和松手也有视觉滞后。现本地调度改为 16ms，使用实际经过时间推进，避免调度阻塞后人物和计时持续变慢；暂停恢复时重新记录时间，不补跑后台时长。小游戏状态层同步修改。本人头像与名牌移除 CSS 过渡，联机通信协议及服务器更新频率保持原值。

回归：`node --test tests/running-page.test.js tests/arena-view-performance.test.js tests/game-store.test.js`，51 项通过；`cd minigame && npm test`，73 项通过。新增真实页面输入路径测试，覆盖 17ms 内人物规则和视图一起移动、松手停止、调度阻塞与后台恢复。

微信开发者工具本地对局采样 35 次状态更新：首帧 12ms、间隔中位数 16ms、P95 17ms；本人过渡时长为 0s，松手后最后三次位置一致。此为模拟器逻辑更新采样，不代表真机显示帧率；真人联机及设备手感仍需真机验证。截图 `/tmp/jinli-share-check/movement-fixed.png`。

小游戏 `npm run build`（含资源生成及 TypeScript 编译）通过。

## 掉落密度调整（用户确认组队为主玩法）

开局 3 秒后开始掉落，每 5 秒一个，全场上限 10 个（包含预警）；满额等待下一间隔。原间隔 360ms，100 秒理论最多 277 个，现最多 20 个。过期生成时间按当前时间向后调度，维持间隔。福袋/礼物/雷分值、组队得失联动与双方互选碰面成队规则保持原值。

规则源、前端、服务端同步生成；新增完整 100 秒掉落频率与同屏上限回归测试，并覆盖满额及过期调度。
