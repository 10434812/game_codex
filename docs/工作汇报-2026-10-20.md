## 二、工作一：小游戏补齐六个页面

**之前的问题**：小游戏只有一个对战画面，进去就是固定房间、机器人陪打，没有首页、没有房间、没有结算，玩完就断了。

**昨天做完的**：

- 首页、房间、结算、商城、资料、战绩 **六个页面全部完成**，从启动到结算形成完整闭环；
- 启动时的隐私授权流程做完：没配好正式协议就不放行，用户撤回授权后也能正确回到授权入口；
- 页面在不同屏幕尺寸下都做了渲染检查（普通屏和长屏各一轮）。

## 三、工作二：真人联机跑通

**这是昨天最关键的一项**。之前所谓"多人"是前端模拟的机器人，现在是真实的两台设备联机：

- 建房、房间码加入、准备、开局、分享邀请，全部走真实服务端；
- 对局中的组队、福袋、快捷表情由服务端裁决，不是客户端自己算；
- 断线能重连，中途退出再进来能恢复到当前局面；
- 结算由服务端确认后发奖，客户端读不到还没结算的结果。

**怎么验证的**：不是只跑单元测试，而是起了真实的数据库和真实服务，用两个账号走了一遍完整流程——建房、加房、准备拦截、开局、实时操作、180 秒打完、结算发奖、用奖励去买东西、再查排行榜。中途还验证了"非房间成员进不来""重复领奖只发一次""注销后旧登录态立即失效"。

## 四、工作三：修掉一批会导致线上事故的问题

这些不是小 bug，都是会在真实对局里出事、但本地演示看不出来的：

| 问题 | 后果 |
|---|---|
| 没点"准备"也能开局 | 房间里有挂机玩家就开打 |
| 结算完房间还停在进行中 | 同一房间无法再开下一局 |
| 旧设备的请求把新账号踢下线 | 换手机登录会被反复顶掉 |
| 连线高亮读的是本地固定 ID | 联机时高亮错人 |
| "开始""再来一局"按钮在长内容末尾 | 短屏手机点不到 |
| 数据库分页在 MySQL 8.4 上报错 | 战绩、收益列表打不开 |

另外把**三端规则对齐**了：小程序、后端、小游戏用同一套随机数据连跑 60 回合，结果完全一致，不会出现"两个版本规则不一样"。
