## 本轮修复的根因

- 后端规则实现落后于客户端：同步实际规则、机器人 ID 和多组锁定队伍语义。
- 未准备成员仍可开局：房间事务在成员核对后校验准备状态。
- 运行中结果可被读取：结果接口在服务端结算确认后提供个人结果。
- 正常结算后房间仍处于进行中：结算事务同步更新房间状态。
- MySQL 8.4 分页错误：将经过边界约束的 LIMIT / OFFSET 参数按驱动兼容方式绑定。
- 缓存清理后结算读取失败：按 mysql2 返回的 JSON 类型读取，兼容字符串和对象。
- 旧请求 401 清理新账号 token：根据请求携带的 token 校验当前会话归属。
- 前后台与操作回复交错：使用生命周期、请求代次和状态版本保护；完成状态保持到本局结束。
- 联机玩家的连线高亮依赖本地固定 ID：改为读取当前状态中实际的自身玩家 ID。
- 房间开始、结果再来一局按钮位于长内容末端：固定在安全区内，短屏和长屏均可操作。
- 离线截图素材与线上封面错位：线上三个封面已通过浏览器核对；截图测试按本地历史素材的真实画面映射，运行时继续使用已核实的线上地址。
- 发布检查引用旧客户端工程：改为检查小游戏工程及对应 AppID，实际接入和材料条件继续保留。

### 真实隔离数据库验收范围

脚本：`back/scripts/test-full-flow.js`。

- 创建独立随机端口 MySQL 8.4 容器，执行仓库全部 SQL 迁移。
- 创建两个参赛测试账号和一个外部测试账号。
- 通过真实 HTTP 验证建房、房间码查询、加房、准备拦截、准备和开局。
- 通过真实 WebSocket 验证个人状态、非成员拒绝、状态通知、表情和重连。
- 通过真实路由验证组队、福袋归属、伪造请求拒绝和重复领取幂等。
- 使用真实 tick 路径加速推进 180 秒对局，确认数据库结算、单次发奖、流水和历史。
- 清理内存对局缓存后，通过持久化数据再次读取两个账号的个人结果。
- 验证结算所得余额购买、穿戴、背包、排行榜和账号注销后的会话失效。

测试账号由测试代码直接创建；微信登录和内容审核属于平台验收项。对局时间采用加速驱动；真实两台设备的网络、触控、音频和运行时表现继续待验收。
