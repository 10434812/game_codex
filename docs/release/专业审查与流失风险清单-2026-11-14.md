# 小游戏专业审查与流失风险清单

审查日期：2026-11-14。范围：原生小程序、Canvas2D小游戏、联机后端、运营后台与发布流程。

## 判断边界

本轮确认了代码和流程问题，并实施下列修复。没有取得可用于归因的真实玩家流失数据，因此“导致流失”在本文指可解释的风险路径，不能解读为已证明某项造成多少用户流失。新增统计上线并积累成熟队列前，不能声称留存已经提升。对局仍为120秒，不恢复游客本地玩法。

P0表示上线前必须核对的正确性或账号资产问题；P1表示直接影响进入、完成和复玩；P2表示运营和扩容能力。优先级描述影响，不代表每项都仍未处理。

## 对局、结算与复玩

| 优先级 | 问题与证据 | 玩家影响 | 当前处理与建议 |
| --- | --- | --- | --- |
| P1 | 接物节奏和连续操作反馈不足。见 `minigame/src/core/RunArena.ts`及生成副本。 | 120秒内缺少持续目标，操作反馈单一。 | 已提高掉落节奏，加入连击、护盾、磁铁与最后15秒冲刺。是否更好玩仍需玩家测试；不要以加功能数量代替趣味性验证。 |
| P1 | 结算后的下一步受房间状态、匹配模式和失败重试影响。 | 想再玩却回到建房或错误界面。 | 已区分匹配局“再匹配”与好友局“原房续玩”，失败保留已确认成绩；并发续玩、取消与迟到响应通过测试。本轮补齐两端移动队列与小程序快照请求的代次隔离，前台恢复不再等待旧请求，旧错误/finally不能影响新请求；仍需真实双设备验收。 |
| P1 | 缺少可传播的本人战绩素材。 | 分享动机与战绩信息不清晰。 | 已提供500×400本人名次/分数/锦鲤币卡片，生成失败回退通用分享。换号/离页失效保护已测；待微信真实发送、接收和点击落地验收。不能按调起分享接口发奖励。 |
| P1 | 音乐、音效、语音、震动缺少独立控制。 | 在安静场合被迫退出或整体静音。 | 两端已提供独立设置；关闭声音仍保留视觉结算。继续保留选择，不通过强制语音制造反馈。 |

## 留存与运营

| 优先级 | 问题与证据 | 玩家影响 | 当前处理与建议 |
| --- | --- | --- | --- |
| P1 | 回访目标主要依靠每日任务，缺少连续与长期进度。 | 玩完一局后没有明确的下一次目标。 | 已增加七日循环签到与四项永久成长奖励。签到断签重计、成长不每日清零；重复点击不重复入账。先观察回访和领取行为，避免叠加大量强制弹窗。 |
| P2 | 榜单能力不能覆盖好友和赛季竞争。 | 长期玩家的同层比较与周期目标不足。 | 已接入明确标注的全服经验榜、同分并列；尚无好友榜或赛季重置。先明确好友关系来源、周期与奖励预算再开发，不把全服榜包装成好友榜。 |
| P1 | 旧“DAU”口径实际是参与对局账号数，缺少体验漏斗与成熟留存。 | 团队无法判断用户在哪一步离开。 | 已补活跃设备/账号、首次设备、顺序漏斗、1/3/7日成熟队列与完局率；旧图已改名。统计上线前历史不可回填，客户端上报亦不等于服务端权威结果。 |
| P2 | 订阅消息、广告缺少真实模板或单元配置与验收。 | 若先放空入口，会形成承诺与体验不一致；错误奖励会破坏经济。 | 尚未接入。取得有效模板、用户主动授权与真实广告单元后再做；奖励须校验，不出售破坏公平的对局能力。不是当前已交付能力。 |
