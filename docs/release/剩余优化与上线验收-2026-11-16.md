## 本轮实现

| 范围 | 结果 |
| --- | --- |
| 匹配与复玩统计 | 双端使用同一份 `minigame/src/core/PlayFlow.ts`，生成 `utils/play-flow.js`。每次请求有独立 attemptId，关联入队、实际开局、取消、失败、真实应用切后台；复玩保留来源场次，只将新场次开始计为复玩成功。服务端按客户端、设备、请求去重统计，展示等待时间、原因、全真人开局和机器人席位比例。不是按调起接口声称匹配成功，也不将切后台当作取消。 |
| 数据隔离 | 迟到的旧账号事件不归到新账号；小程序 token 正常续签可延续同一请求。事件只携带白名单属性，失败原因为枚举，不携带原始异常或凭证。应用重启丢失的内存关联不能补成成功，尚未开局的请求保留在分母中。 |
| 首屏资源 | 按默认景区「万里长城」启动路径，小程序预载任务从 35 项减至 11 项（去重资源 33→11），最多 4 个并发；超时离开启动页或卸载后停止调度剩余任务。只预载当前景区和首页所需图，不提前加载全部头像、景区和对局效果。保留原有授权、最低展示时间与配置/登录预算。新增授权后准备耗时事件，用于积累真实设备样本。 |
| 首页视频 | 去除重复的背景视频，保留当前景区卡片视频和静态背景；同时播放从 2 路减至 1 路。切景区、离页时暂停，隐藏页移除视频节点；迟到的 nextTick 不会重启旧视频。 |
| 下一目标 | 结算后异步读取服务端永久成长进度，优先提示可领取项，否则选最接近完成的目标，展示实际剩余局数/经验与原有奖励。领取入口打开任务页，不另发奖励；加载失败不阻塞成绩或复玩。跨账号、离页、旧场次响应均隔离。小游戏源 `GrowthGoal.ts` 生成小程序副本。 |
